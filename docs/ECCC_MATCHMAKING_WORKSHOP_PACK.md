## 90-second introduction

Agent Recovery Platform is building verified recovery for autonomous AI-agent side effects across multiple tools and systems.

Prevention, IAM, SIEM and agent observability can show or limit what an agent does, but they do not by themselves prove that a harmful business-system change was recovered after it already happened.

Our lifecycle is:

**incident → containment → evidence → recovery / compensation → replay / regression → verified restoration**

Before deployment, we map consequential write actions and require explicit Recovery Contracts. During an incident, the platform preserves action and side-effect evidence, contains affected authority and reconstructs blast radius. It then executes only trusted recovery or compensation paths, verifies the resulting external state and records irreversible residuals. Authority is restored only when current scope-bound evidence supports it.

The current product already has a framework-neutral evidence model, OTel-compatible normalization, versioned Recovery Contracts, restart-safe incident state, a read-only operator console, a repeatable owned multi-surface pilot and an Agent Recoverability Assessment.

We are looking for a consortium where Agent Recovery acts as **technology provider and owner of the recovery work package**, not as first-time coordinator.

## Pilot KPIs

Measure per deployment:
- percentage of consequential actions with a valid trusted recovery path;
- time to containment;
- time to verified recovery;
- recovery/compensation success by action class;
- irreversible residuals surfaced;
- unsafe/false restoration attempts rejected;
- integration engineering effort;
- operator task completion time;
- replay/regression outcome after remediation.

Separate evidence classes:
- synthetic benchmark;
- owned sandbox;
- external pilot;
- production deployment.

Never present lower evidence classes as production security effectiveness.

## Call-selection rule

### Prefer AI4SME when
- SME deployments are central;
- the consortium wants usable, low-friction cyber-resilience tooling;
- Agent Recovery can own a clearly measurable deployment work package;
- the AI component supports investigation, risk/recovery reasoning or automation while deterministic gates retain authority.

### Prefer CYBERAI when
- incident recovery / trustworthy AI is a central technical objective;
- relevant NIS2/cyber authorities, hubs or strong cybersecurity operators are present;
- the consortium does not force Agent Recovery into generic detection/SIEM scope.

Reject/deprioritise when the project requires:
- generic SIEM/EDR/IAM scope unrelated to verified recovery;
- unsupported production-security claims;
- unacceptable co-financing exposure;
- background IP transfer or exclusivity;
- consortium padding without real deployment responsibility.
